# 大肥鱼 · QQ 陪伴机器人

一个把自己"当成群里的人"来聊天的小机器人：会接话、会撒娇、会用她自己的声音说话、会唱歌、会偷表情包，还会每天写一篇自己的日记发到 QQ 空间。带一个本地网页控制台，所有设置点一下就能改，改完立即生效。

Node 20+，**零 npm 依赖**（全用 Node 内置模块），单进程，跑在一台普通 Windows 电脑上即可。

> 公开版说明：这个仓库是"干净版"，**不包含**远程控制手机那一整套能力，也不带任何人的语音素材、聊天记录和登录令牌。

---

## 她能做什么

**聊天**

- 拟人节奏：先按"读完想完打字"的节奏停顿，长句拆成两三条发出去（`|||` 分条，条间 0.7~2.3 秒）
- 会引用你刚说的那条、会补一句"对了……"、会攒几条一起回（连发合并，不刷屏）
- 有心情（摸鱼 / 炸毛 / 困 / 温柔…）、有关系（主人 vs 群友，语气和条数不同）
- 群里会自己判断"这句该不该接"（相关性打分 + 频率限制 + 静默时段），不是每句都抢
- 长期记忆 + 按人记账：同一个人换群、换私聊，她认识的是同一个人
- 会主动开话头：安静太久时自己冒个泡（默认关，开了容易显得刻意）

**声音**

- 本地克隆音色（GPT-SoVITS api_v2，零样本，一段参考音频就够）
- 合成失败**不会**用系统自带语音顶替（音色不对，宁可不发）
- 想用嘴说话时：**先把文字发出去**，语音在后台等模型加载好再补一条

**唱歌**

- 点歌（真歌）：从 B 站找原曲 + 官方伴奏 → Demucs 拆人声 → RVC 换成她的音色 → 保留原伴奏混回去。
  旋律、节奏、咬字都是原唱的，只换音色；同一首歌第二次点走缓存，秒回
- 儿歌 / 哼一句：TTS 逐字合成 → 按旋律逐音变调 → PCM 交叉淡化拼接 → 程序合成伴奏
- 音频一律后台生成：文字先回，唱好了再发

**其它**

- 表情包：群里有人发表情自动收进素材库（严格判定，普通图片不收），聊天时按话题挑一张
- QQ 空间：每天写一篇日记（第一人称、几十字、不重复），自动发成说说；可见范围可配（所有人 / 好友 / 仅自己）
- 知识库：`data/kb/` 里的 `.md` / `.txt` 切片，按关键词注入上下文，答不上就说不知道
- 网页控制台（默认 `http://127.0.0.1:3092`）：模型、人格/角色卡、音色、表情库、日记、空间、服务状态、事件日志，全在本地

## 它是怎么接进 QQ 的

```
QQ 客户端 ── OneBot11 网关（SnowLuma / NapCat 等）──正向 WebSocket──▶ 本程序
                                                        │
                          ┌─────────────────────────────┴─────────────────────────────┐
                          │ gate（该不该回）→ context（人格/记忆/历史）→ llm（出契约 JSON） │
                          │ → guard（不许自曝/不许说技术细节）→ outbound（拆条/脱敏/引用）    │
                          │ → transport（发回 QQ）                                          │
                          └───────────────────────────────────────────────────────────────┘
```

- 输入输出都走标准 OneBot11：`send_group_msg` / `send_private_msg` / `get_login_info`
- QQ 空间说说用 SnowLuma 的扩展动作（`send_qzone_msg` 等）。换成只支持标准 OneBot 的网关时，
  空间功能会自己降级（日志会写清楚"网关不支持空间动作"）
- 输出契约：每一轮模型只输出一个 JSON（`segments` / `mood` / `sticker` / `follow` / `memory` / `action`），
  程序负责把它变成"像人发的"几条消息

## 快速开始

### 0. 你需要准备

| 必需 | 说明 |
| --- | --- |
| Windows 10/11 | 别的系统理论上能跑，但启动方式按 Windows 写的 |
| Node.js ≥ 20 | 本项目零 npm 依赖，装 Node 就够 |
| 一个 QQ 小号 | 建议新号，别用主号 |
| OneBot11 网关 | SnowLuma（空间功能需要它）或 NapCat 均可，正向 WS |

| 可选（没有只影响对应功能） | 说明 |
| --- | --- |
| GPT-SoVITS `api_v2` | 克隆音色，监听 `127.0.0.1:9882` |
| RVC 换声服务 | 唱歌换音色，监听 `127.0.0.1:9885`（CPU 也能跑） |
| Demucs + ffmpeg + Python | 点歌时拆人声 / 混音 |
| 一个 OpenAI 兼容模型接口 | DeepSeek / 任意兼容网关都行 |

### 1. 起程序

```bash
git clone https://github.com/zouxinhao594-alt/fatfish-qq-bot.git
cd fatfish-qq-bot
node src/main.mjs --data data
```

> 不想装 git？页面右上角 `Code → Download ZIP`，或到 [Releases](https://github.com/zouxinhao594-alt/fatfish-qq-bot/releases) 下载最新版，
> 解压后进入目录跑同一条命令 `node src/main.mjs --data data` 即可。不需要 `npm install`，这个项目没有依赖。

控制台地址会打印在终端里（默认 `http://127.0.0.1:3092`）。第一次运行会在 `data/` 下生成 `config.json`
（默认全是安全值：**演练模式**、白名单为空、语音关闭）。

### 2. 在控制台里填四条就能聊了

打开控制台 → 「设置」页：

1. **网关地址**：默认 `ws://127.0.0.1:3001`
2. **网关访问令牌**：网关那边如果设了 `access_token`，填一样的；没设留空
3. **模型**：渠道地址 + API Key + 模型名（「模型」页可以测通、可以按用途分别指定）
4. **群白名单** / **管理员 QQ**：不填白名单她一条都不接；填了管理员就等于认主

填完把**演练模式**（`dryRun`）关掉，她才会真的往 QQ 发消息。

### 3. 语音（可选）

语音服务是**全程常驻**的：你自己把它开机自启（Windows 任务计划/启动文件夹都行），机器人这边只负责用——
这样她随时开口都是自己的声音，零等待，也不会出现"挂着挂着模型被关掉"的情况。

1. 自己起一个 GPT-SoVITS `api_v2`（装法随意），监听 `127.0.0.1:9882`，并设成开机自启
2. 控制台「音色」页：引擎选「本地克隆引擎」，接口填 `http://127.0.0.1:9882`
3. 参考音频填一段**几秒干净人声**的 wav 绝对路径，并把那段话的原文填到「参考原文」
4. 点「试听」，听到的是她的声音就成

> 想省内存也可以打开「本地语音/换声按需启动」（`voiceOnDemand`）：机器人用时自己拉起、闲置再关。
> 代价是闲置后第一次要等 3~4 分钟模型加载，而且得在设置页「语音服务启动脚本」（`ttsStartScript`）
> 填一个你自己写的 `.ps1` 启动脚本。**默认没开，一般不需要。**

> 参考音频请用**你有权使用**的声音，不要克隆真人（尤其是未经同意的他人）。

### 4. 唱歌（可选）

- 儿歌 / 哼一句：只要语音通了就能唱（逐字合成 + 变调）
- 点歌（真歌）：还需要 RVC 换声服务（常驻 `127.0.0.1:9885`）和 Demucs。到设置页填：
  - `rvcPython`：RVC 的 venv 里的 `python.exe`（绝对路径）
  - `rvcScript`：监听 9885 的那个服务脚本路径
  - `demucsPython` / `demucsDir`：Demucs 用的 python 与缓存目录

> 点歌默认只有管理员能点（要跑几分钟 CPU），可以在设置里放开。

## 配置项

`data/config.json` 是唯一配置文件，控制台「设置」页就是它的可视化界面（每一项都有中文说明）。
仓库里的 `config.example.json` 是一份带注释感的示例，可以参考着填。

比较常用的：

| 键 | 作用 |
| --- | --- |
| `dryRun` | 演练模式：只记日志不发消息。**第一次务必开着调** |
| `groups` / `ownerUin` | 群白名单 / 管理员 QQ（认主） |
| `napcatWs` / `napcatToken` | OneBot11 网关地址与令牌 |
| `personaFile` / `personaRolesDir` | 人格文件名 / 角色卡目录（`data/roles/*.md`，控制台可切换） |
| `ttsEnabled` / `ttsEngine` / `ttsEndpoint` | 语音总开关、引擎、接口 |
| `ttsRefAudio` / `ttsRefText` | 参考音频路径 / 那段话的原文 |
| `ttsStartScript` | 只有开了「按需启动」才用得上：拉起语音服务的脚本（留空用 `tools/start-voice.ps1`） |
| `voiceOnDemand` | 本地语音/换声**按需启停**，默认 **关** = 全程常驻（推荐） |
| `ttsAllowSapiFallback` | 合成失败时是否退回系统自带语音（默认 **否**） |
| `songSingEnabled` / `songOwnerOnly` | 点歌开关 / 是否只有管理员能点 |
| `rvcPython` / `rvcScript` / `demucsPython` / `demucsDir` | 唱歌用的本地程序与目录 |
| `qzoneDiaryEnabled` / `qzoneUgcRight` | 日记是否发空间 / 说说可见范围（1 所有人、4 好友、64 仅自己） |
| `voiceChance` / `bubbleMax` | 自动改语音的概率 / 一轮最多拆几条消息 |

## 数据目录（都不进版本库）

```
data/
├── config.json          配置（含令牌 / API Key，别提交）
├── persona.md           人格（控制台可编辑）
├── roles/               角色卡（可选，多张卡切换）
├── kb/                  知识库（.md / .txt，会被切片注入）
├── memory.json          长期记忆
├── people.json          按人记账
├── diary/               她的日记（jsonl + 按天 md）
├── stickers/            表情素材库
├── voice/               参考音频（本地）
├── songs/               点歌用的本地音频（可选）
├── media/               生图、合成语音、唱歌成品、服务日志
├── state/               运行时状态（端口、模型路由、歌曲缓存）
└── logs/                按天 jsonl 事件日志
```

## 安全与隐私

- **全部本地运行**：消息、记忆、日记、日志都在你自己的机器上，不上传
- **群白名单**：不在名单里的群一条都不接
- **主人权限**：点歌、写文件、执行命令这类只对管理员开放
- **不许自曝**：内置守卫会把"我是 AI / 我的模型是 / 我的训练数据"这类回复拦掉或改写
- **出站脱敏**：token、密码、本机路径在发出去之前替换掉
- **演练模式**：默认开启，调好再关

发布到自己的仓库前，请确认 `data/`、日志、参考音频都已经在 `.gitignore` 里（本仓库已经写好）。

## 已知限制

- 语音/唱歌依赖本地模型（常驻内存约 1~2 GB）；本版按"全程常驻"设计，开口零等待。
  如果开了「按需启动」，闲置后第一次用要等 3~4 分钟模型加载（此时会先回文字、语音稍后补发）
- 点歌在纯 CPU 上整首要几分钟；默认只截 60 秒
- QQ 空间是 SnowLuma 的扩展能力，标准 OneBot 网关没有
- 看图 / 生图需要你的模型支持视觉 / 生图（不支持就当没有这个功能）
- 这是一个"一个人用"的规模，没有多租户、没有权限系统、没有云端存储
